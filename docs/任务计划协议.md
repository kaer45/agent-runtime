## 任务计划协议

```json
{
    "tasks":[
        {
            "id": "T1",
            "tool": "get_weather",
            "arguments": {
                "city": "成都"
            },
            "dependencies": []
        },
        {
            "id": "T2",
            "tool": "get_current_time",
            "arguments": {},
            "dependencies": []
        },
        {
            "id": "T3",
            "tool": "brewing",
            "arguments": {
                "weather": {"from_task": "T1"},
                "current_time": {"from_task": "T2"}
            },
            "dependencies": ["T1","T2"]
        }
    ]
}
```



## 字段说明

| 字段           | 类型     | 必填 | 含义                                                         | 示例                 |
| :------------- | :------- | :--- | :----------------------------------------------------------- | :------------------- |
| `tasks`        | `Array`  | 是   | 任务列表，包含本次执行计划中的所有任务对象。                 | `[{...}, {...}]`     |
| `id`           | `String` | 是   | 任务唯一标识。通常以 `T` 开头加数字，必须全局唯一（或同一批次内唯一）。 | `"T1"`, `"T2"`       |
| `tool`         | `String` | 是   | 要调用的工具函数名称，必须与系统中注册的工具名完全一致。     | `"get_weather"`      |
| `arguments`    | `Object` | 是   | 工具调用的参数字典。如果是无参函数，传入 `{}`。              | `{"city": "成都"}`   |
| `dependencies` | `Array`  | 是   | 前置依赖的任务 ID 列表。当前任务必须等待列表中的所有任务都执行成功后，才能开始执行。如果是起始任务，传入 `[]`。 | `["T1", "T2"]`       |
| `from_task`    | `String` | 否   | 引用另一个任务的完整结果                                     | `{"from_task":"T1"}` |

后续如果需要获取某一次任务结果的特定字段，可以再进行拓展。



## 参数引用机制（数据流）

在 `arguments` 中，如果某个参数的值依赖于前序任务的输出，使用 **`{"from_task": "任务ID"}`** 的格式进行占位。

- **示例**：`"weather": {"from_task": "T1"}` 表示在执行 `T3` 时，将 `T1` 任务的 `result` 作为 `weather` 参数的值传入。
- **约束**：`from_task` 指定的 ID 必须存在于本次的 `tasks` 列表中，且必须包含在当前任务的 `dependencies` 数组中，否则视为非法引用。

------

## 约束与校验规则（代码需实现的防御）

为了确保大模型输出的协议是合法的，你的 `TaskScheduler` 在接收数据后、启动任务前，必须进行以下校验：

1. **ID 唯一性**：所有的 `id` 不能重复。
2. **依赖存在性**：`dependencies` 里的任务 ID 必须在 `tasks` 列表中存在。
3. **引用合法性**：`arguments` 里的 `from_task` 必须在 `dependencies` 中声明，防止模型“忘了写依赖但用了引用”。
4. **无环性（DAG 校验）**：任务图必须是有向无环图（利用你已写好的 Kahn 算法）。
5. **参数匹配**：`tool` 调用的 `arguments` 必须在目标工具的 JSON Schema 中有定义。
